# functions/itinerary_theme 작업 규칙

GCP Cloud Functions로 배포되는 Python 서버리스 함수. Gemini API를 호출해 여행 동선(itinerary) 테마를 생성한다.

## 구조

| 파일 | 역할 |
|---|---|
| `main.py` (459줄) | 엔트리포인트. 이 저장소에서 가장 큰 단일 파일 — 분해 우선순위 1순위 |
| `gemini_client.py` | LLM 호출 |
| `prompts.py` (241줄) | 프롬프트 템플릿 |
| `geo_utils.py` | 좌표/거리 계산 |
| `db.py` | 데이터 접근 |
| `data/transport_hubs.json` | 정적 데이터 |
| `*.ps1` | 배포/로그/VPC 스크립트 — **실행 금지(권한 차단), 읽기만** |

## 규칙

- **자동 검증 수단이 전혀 없다.** 테스트도 타입 체커도 CI도 없고, `test.py`는 정식 테스트 스위트가 아니다. 여기를 고칠 때는 프론트엔드보다 훨씬 보수적으로 접근하고, 변경 전에 무엇으로 검증할지 먼저 정한다.
- 프롬프트 문자열(`prompts.py`)을 바꾸면 **LLM 출력 형식이 깨질 수 있다.** 파싱하는 쪽(`main.py`)을 함께 확인하지 않은 프롬프트 수정은 하지 않는다.
- API 키·프로젝트 ID·엔드포인트를 코드나 로그에 노출하지 않는다. `function-config.yaml`에 값이 있으면 그대로 두고 하드코딩된 비밀만 지적한다.
- `__pycache__/`는 산출물이다. 편집·읽기 모두 차단돼 있다.
- 이 함수는 프론트엔드 리팩토링의 **직접 대상이 아니다.** 프론트 작업 중 여기 파일을 고치게 됐다면 범위를 벗어난 것이므로 먼저 사용자에게 확인한다.

## LLM 호출 코드를 다룰 때

- 모델 ID, 토큰 한도, 재시도 정책을 바꾸는 변경은 비용과 응답 품질에 직결된다. 수치 근거 없이 조정하지 않는다.
- 프롬프트 개선을 제안할 때는 before/after 출력 예시를 함께 제시한다.
