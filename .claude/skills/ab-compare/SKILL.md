# A/B 정량 비교 절차

주제: $ARGUMENTS

이 저장소의 목표는 "고쳤다"가 아니라 **"수치로 증명했다"**이다. 아래 순서를 건너뛰지 않는다.

## 0. 비교 설계를 먼저 확정한다 (코드 작성 전)

사용자와 다음을 합의하기 전에는 구현을 시작하지 않는다. 불명확하면 `AskUserQuestion`으로 묻는다.

- **비교 대상**: A안과 B안이 정확히 무엇인가 (버전 포함)
- **동일 조건**: 같은 화면·같은 검증 규칙·같은 API 계약으로 맞춘다. 한쪽만 기능이 더 많으면 비교가 무효다
- **측정 지표**: 아래 표에서 최소 3개를 고른다. 고르지 않은 지표는 측정하지 않는다
- **판정 기준**: 어떤 결과가 나오면 A안을 택하는가. **측정 전에** 정해 둔다 (사후 합리화 방지)

## 1. 지표 선택표

| 축 | 지표 | 측정 방법 | 신뢰도 |
|---|---|---|---|
| 번들 | 해당 라이브러리 기여분 gzip bytes | 라이브러리 제거 전후 빌드 diff | 높음 |
| 번들 | 초기 JS 전송량 | `dist/assets/*.js` gzip 합계 | 높음 |
| 코드량 | 같은 폼 구현에 필요한 줄 수 | `wc -l` | 높음 |
| 타입 안전성 | `any`/타입 단언 개수, 타입 추론이 끊기는 지점 | `rg "as any|as unknown"` + 수동 확인 | 중간 |
| 런타임 | 입력 시 리렌더 횟수 | React Profiler 또는 렌더 카운터 계측 | 중간 (환경 변동) |
| 런타임 | 상호작용 반응 시간 | Playwright + `performance.measure` | 중간 |
| 빌드 | type-check / build 소요 시간 | 3회 측정 후 중앙값, cold/warm 명시 | 낮음 (머신 의존) |
| DX | 검증 스키마 재사용 가능 여부 | 코드로 확인 (정성, 수치 아님) | — |

**낮은 신뢰도 지표를 근거로 결론을 내지 않는다.** 빌드 시간 차이 5%는 노이즈다.

## 2. 실행

1. **베이스라인 브랜치를 만든다.** `git status`가 clean한지 먼저 확인한다.
2. A안 상태에서 `benchmark-runner` subagent로 측정 → 결과를 기록한다.
3. B안을 구현한다. **비교 대상 외의 것을 함께 바꾸지 않는다** (리팩토링과 비교 실험을 섞으면 원인 귀속이 불가능해진다).
4. B안 상태에서 **같은 명령으로** 측정한다. 다른 명령·다른 캐시 상태로 잰 값은 비교할 수 없다.
5. 런타임 지표는 3회 이상 측정해 중앙값과 편차를 함께 적는다. 1회 측정치는 쓰지 않는다.

## 3. 기록

`docs/refactor/` 아래에 `NN-주제.md`로 저장한다. 형식은 `docs/refactor/TEMPLATE.md`를 따른다.

대화에만 남기면 컨텍스트 압축과 함께 사라진다. **파일로 쓰기 전에는 이 작업이 끝난 것이 아니다.**

## 4. 결론 작성 규칙

- 측정하지 않은 축에 대해서는 "측정하지 않음"이라고 쓴다. 일반론으로 채우지 않는다.
- 차이가 노이즈 수준이면 "유의미한 차이 없음"이라고 쓴다. 억지로 승자를 만들지 않는다.
- 수치가 직관과 반대로 나왔다면 그것이 이 실험의 가장 가치 있는 결과다. 숨기거나 재측정으로 뒤집으려 하지 말고 그대로 적는다.
- 정성적 장점(DX, 학습 곡선)은 별도 섹션에 분리하고 **수치와 섞지 않는다.**

## 이 저장소의 사전 정보

- `react-hook-form`은 dependencies에 있으나 **사용처가 0개**다. 즉 RHF 비교는 "제거 후보 검증"이 아니라 새로 구현해야 하는 실험이다.
- TanStack Form은 `src/features/auth/hooks/`의 4개 훅에서만 쓰인다 — 비교 대상 화면으로 가장 적절하다.
- zod는 6개 파일에서 사용 중. 두 폼 라이브러리 모두 zod resolver를 지원하므로 **검증 스키마를 공유해 조건을 동일하게 맞출 수 있다.**
- `nextjs/k6-tests/`에 부하 테스트 스크립트가 이미 있다. 서버 측 지표가 필요하면 새로 만들기 전에 재사용을 검토한다.
